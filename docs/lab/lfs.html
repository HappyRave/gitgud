What every variant shares

proposal
  • Clone: pointers first, then choose. git clone runs with LFS smudge off (seconds, not an hour), so every file's size is known before anything big downloads. The choice is made with real sizes, then gitgud downloads what you chose, with the clone's existing LFS progress.
  • Stored as git-lfs config in the repo's .git/config (never committed): pull, checkout and Sourcetree respect it.
  • A skipped file isn't lost: its row shows ☁ "not downloaded" in the working copy, history and file tree. The viewers already fetch one on open (≤ 25 MiB at once, a Fetch button above that). "Download" on any file, folder or selection.

Getting a skipped file later

proposalMax: "what when I need to get one of the ommited files later?"

Four ways in, from the most automatic to the most manual. Each one downloads now (git lfs pull -I on those paths) and, so the file doesn't fall back to a pointer, keeps it in the list.

  • 1 · Add the scene or prefab you're starting on. Its whole dependency tree comes down, and later pulls keep it up to date. Best when you know what you're about to work on.
  • 2 · Unity asks for it. When you open a scene in Unity that uses skipped files, Unity fails to import them and logs each one. gitgud reads Unity's Editor.log while the project is open and offers them in one click (state below). open, test the exact log line for a pointer file.
  • 3 · Download in gitgud. ☁ rows in the working copy, history and file tree: Download on a file, a folder or a selection. Opening a skipped file in a viewer fetches it (as today: 25 MiB at once, a Fetch button above).
  • 4 · Download everything, in the dialog's footer: the repo becomes complete again.
  • fact Why "keep it in the list" matters: git-lfs applies the include list on every checkout and pull. A file downloaded once but not in the list goes back to a pointer the next time someone changes it. So every download above adds its paths to the list, under "Kept by you", until you remove them.
