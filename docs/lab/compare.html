What every variant shares

proposal
  • Any two of: a commit, a branch (local or remote), a tag, the working copy, a stash. A is the older or "from" side, B the "to" side; Swap flips them.
  • Two modes, named in words: What B brings (from where they split, the default for branches) and Snapshot difference (the default for two commits on one line, where both agree).
  • Files open in the existing viewers with A on the left and B on the right: diff, image compare, 3D side by side / swipe, Unity YAML structure.
  • Commits only on each side are listed, so "what's in it" reads as commits, not only as files.

C

Pin a base

proposal

Pin any row (P on a row, or right-click "Pin as base"). From then on, every row you select is shown against the pin instead of its parent, so ↑↓ walks the history and the inspector shows everything since the pin, growing step by step. Unpin with P again. A browsing tool more than a comparing one.

D

Branch card before merging

proposal

Narrow and practical: compare is about branches about to meet. Hovering a branch in the sidebar (or its right-click "Compare with current") opens a card: commits each way, files by kind, and the merge prediction gitgud already runs (which files would conflict). "Open the diff" shows the files; "Merge…" starts the merge dialog.

Open questions

  1. A, B, C or D? decided 2026-11-26 B (Max: "B Compare view"), with A's Ctrl+click and "Compare with current" as ways in.
