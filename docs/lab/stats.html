gitgud lab · round R8 · 2026-11-25

App stats in the strip

Brief (Max, 2026-11-25): "I'm not sure the little git version and path in the bottom right corner is useful. What would be more useful is some app stats, like cpu, ram, and cache usage (in each repo). Don't make it boring, like not just CPU: 2%. but must remain 100% clear and readable. The cache stat can be clicked to show a little context window with a clear button."
proposal Everything below is a proposal; nothing is decided. Strips are drawn at the app's real size (24 px, 11.5 px text, dark theme tokens), then once at 2× so details can be judged.

What the numbers mean

proposal
  • CPU: gitgud's whole process tree (the app, its WebView2 processes, the git it runs), as a share of the whole machine like Task Manager. Sampled every 2 s, paused while the window is minimised.
  • RAM: the same tree's working set. WebView2 is most of it; hover splits it ("app 140 MB · view 290 MB · git 0").
  • Cache: what gitgud itself keeps for the open repo: 3D previews on disk (meshes, shrunk textures; LRU-capped at 1 GB), Unity references (GUID index), plus the in-memory model cache. Not git's data: LFS objects and the commit-graph file are listed as "not touched".
  • The git version and path move to Settings › Git only (it now has a whole section for them).
S1

Trace

Claude's pick

CPU is a 40-second trace with the number after it: a single "2%" says nothing, the shape says "it spiked when I opened that scene and settled". The trace turns amber above 50%, orange above 85%. RAM and cache stay plain numbers with short labels. Cache is a button with a drum icon.

S2

Meters

proposal

Hardware-style pips: CPU as 8 segments that fill and warm up. The cache gets a meter too, against the disk cache's 1 GB cap, so "how full" reads before "how big". RAM stays a number: there is no honest scale for it.

S3

Lane

proposal

The app icon's idea in the strip: CPU history drawn as a little commit-graph lane, one dot every 4 s, the dot's size is the load. Quirky and on-brand; the number after it keeps it exact.

S4

Words

proposal

No graphics: the CPU number gets a word ("idle", "ticking", "busy", "flat out") and a dot that beats while busy (steady with reduced motion). Reads like a sentence: "idle 2% · 412 MB in use · 922 MB cached".

C1

Cache popover

Claude's pick

Opens above the cache stat (S1 shown), closes on Esc or a click outside. Says what Clear removes, what it costs (the next scene opening rebuilds), and what it never touches. One button; no confirm, since everything it removes rebuilds itself.

Open questions

  1. Which strip: S1 Trace, S2 Meters, S3 Lane or S4 Words? Claude's pick: S1 the trace is the only one that adds information over a number (what happened in the last 40 s), and it stays exact.
  2. CPU scale: share of the whole machine (Task Manager, 100% = every core) or of one core (100% = one core busy)? Claude's pick: whole machine it matches what people compare it with.
  3. RAM: count WebView2's processes too? Claude's pick: yes it's the real footprint; hover splits it.
  4. Library tab (no repo open): hide the cache stat, or show all repos' caches together? Claude's pick: show the total with the popover listing the biggest repos, each with its own Clear.
  5. Does Clear also drop the in-memory model cache (the 768 MB budget in the viewer)? Claude's pick: yes otherwise "Clear" frees disk but RAM stays the same, which reads as broken.
