The shared frame

proposal · Claude's pick

Every viewer keeps R6's frame so all previews read as one family: the file path and a kind pill on the left of the header; then how the two versions are arranged, the format's compare modes (Side by side, Swipe, Onion where pixels overlay; Stacked / Overlay for sound); Expand to fill the window. Format controls (shape, slices, which rows, Wave / Spectrogram) float in the pill over the view; numbers live in the caption line along the bottom, with deltas coloured added / removed / changed. Text-based Unity files already open in the structural diff, so they get R6's prefab switch grown to three: Visual | Structure | Source. The alternative, each viewer mimicking its own tool (a DAW, a PDF reader, a spreadsheet), would make ten different UIs to learn. Not every frame below follows this yet (some put view switches in the header); the questions ask whether to make it the rule.

One lane per version on a shared time axis and playhead (press play to hear the example). A / B swaps which version you hear at the same moment, like a DAW's compare. Stereo files get two thin lanes per version.

Good

  • A/B at the same position is how you actually judge sound.
  • Length and loudness changes are spelled out.

Costs

  • Two lanes halve the height.
  • The webview decodes WAV, MP3, OGG and FLAC but not AIFF, and resamples everything: AIFF decoding and the true rate, channels and loudness come from Rust (a decoder crate, see question 6).

decided 2026-11-24 · every Claude's pick below

Max: "Go with your picks". Each answer below is now decided; details in docs/lab/decisions.md.

  1. Shared frame as a rule: the header holds only how the two versions are arranged (Side by side / Swipe / Onion, or Stacked / Overlay for sound); every other view switch lives in the pill over the view; Expand on the right? Claude's pick: yes, and the frames get redrawn to follow it.
  2. Per format: which default, and which extra modes are in scope? Most "not picked" variants would come back as a mode inside the pick (A2 → Overlay, P2 → Text, T2 → Onion, AC2 → Dope sheet, D2 → nested cells, V2 → scrub preview, U2 → Map). Claude's picks for the default: M1, A1, P1, T1, S1 (as today), V1, SP1, AC1, D1, U1; extra modes later, one at a time.
  3. Unity text files (.mat, .anim, .asset, .unity): R6's prefab switch "Structure | 3D" becomes Visual | Structure | Source, opening in Visual and remembering the last choice? Claude's pick: yes, remembered per format (prefab and .mat can differ).
  4. Audio and video on open: never autoplay, video starts muted, one app-wide volume. Claude's pick: yes to all three.
  5. Remembered choices (A/B, Stacked/Overlay, PDF Text, Changed rows, Curves/Dope sheet…): per format, like R6's shading? Claude's pick: per format.
  6. New dependencies (your rule: ask first): pdf.js for PDF (frontend, a few MB); a font parser in Rust (ttf-parser or skrifa, plus WOFF2 decompression); an audio decoder in Rust (symphonia) for AIFF, true sample rate, loudness and the spectrogram; an MP4/MOV container parser in Rust (mp4 / re_mp4-style, no ffmpeg) for fps and codec. Claude's pick: all four, nothing heavier (no ffmpeg/ffprobe).
  7. A change only in the .meta (re-slicing, import settings): open the asset's viewer with an "import settings changed" note? Claude's pick: yes.
  8. "Your mesh" for .mat and "3D" for .anim need a reverse lookup (which prefabs use this material or clip). Pick the first user automatically, let you choose from a list, or drop it for now? Claude's pick: a list, first entry preselected.
  9. TextMeshPro font assets (what Unity UI actually renders): add an SDF-atlas + glyph-table viewer to this batch, or later? Claude's pick: later; the .otf/.ttf viewer first.
  10. Scenes: one merged Changes view (U1 as drawn: moved objects as a ghost) or R6's side by side with both tinted? And above what size does a scene open in Structure first? Claude's pick: merged view as an extra mode next to side by side; Structure first above 20k objects (a guess, to measure).
  11. Auto-download: keep the 25 MiB LFS rule for audio and video too? "Open in default app" writes the old version to a temp file in the OS temp folder, deleted when gitgud closes. Claude's pick: yes, and that temp-file rule.
  12. Order of building: Claude's pick: fonts, .mat (reuses R6), audio, data tables, PDF, video, sprite sheets, curves, scenes last (biggest). SVG is already there.
